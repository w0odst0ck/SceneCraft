## 1. 产品定位

**一句话**：SceneCraft 是一条 **AI 短剧全栈流水线**——输入一句话概念，输出成套可交付的视频产物（剧本 / 美术设定 / 分镜 / 提示词 / 剪辑蓝图 / 视频片段）。

**解决什么问题**：
传统"一键生成"是黑箱：中间产物改不了、断了不能续、跨项目不能复用。SceneCraft 把生产拆成 **7 个独立工作室**，站与站之间只通过**显式落盘的产物契约**通信——**随时停、改、续**。

**给谁用**：个人创作者 / 小团队（1 人 + AI 助手），需要可控、可迭代的短视频生产流程。

**边界（明确不做）**：
- 不做通用视频编辑器（剪辑仍以时间线蓝图 + 外部工具为主）
- 不做 SaaS / 多租户服务
- 本地视频模型定位为**测试档**（质量不达成品级，见 §4）

## 2. 核心概念

### 2.1 七工作室（站）

| # | 工作室 | 归入 Agent | 输入 | 输出产物 |
|---|---|---|---|---|
| 1 | 📝 剧本 | producer + writer | concept（一句话） | `01_script/script.json` |
| 2 | 🎨 美术 | art_director | script | `02_art/visual_bible.json` |
| 3 | 🎬 拍摄 | director + cinematographer + actor | script + visual_bible | `03_shoot/shot_list.json` |
| 4 | 🧠 提示词 | prompter | shot_list + visual_bible | `04_prompt/prompt_list.json` |
| 5 | ✂️ 剪辑 | editor | shot_list + script | `05_edit/editing_blueprint.json` |
| 6 | 🖥️ 渲染 | ComfyUI 本地 / （未来）API | prompt_list + editing_blueprint | `06_render/*.webm` + `render_plan.json` |
| 7 | 🧐 质检 | critic（横切） | 任意站产物（`--input-stage`） | `07_qc/qc_report.json` |

### 2.2 产物契约与血缘（可信协作的底座）

- **JSON 为准**：一切自动化流程只认 JSON；MD 是人读视图，**只读**
- **血缘字段**：每个产物带 `upstream_hash` / `edited_by: ai|human` / `version` / `output_hash`
- **人工保护**：`edited_by: human` 的产物，AI 重跑**不得静默覆盖**（架构级防误改）
- **断点续跑**：任一站失败/中断，`--from <站>` 从该站继续，已完成产物保留

### 2.3 两环境（成本与质量分层）

| 环境 | 后端 | 用途 | 成本 |
|---|---|---|---|
| `SCENE_ENV=test` | 本地 ollama（qwen3.5:9b 等） | 开发 / 链路验证 | ¥0 |
| `SCENE_ENV=prod` | DeepSeek（deepseek-flash） | 成品剧本质量 | 按量 |

切换：`source scripts/scene-env.sh test|prod`（run_pipeline 启动会打印当前环境）

## 3. 工作流（怎么用）

### 3.1 全链路一条命令

```bash
cd projects/SceneCraft
source scripts/scene-env.sh test                    # 测试环境（本地 ollama，¥0）

python studios/run_pipeline.py \
    --project my-drama \                            # 项目 ID
    --concept "雨夜便利店的神秘顾客，冷光与霓虹" \      # 一句话概念
    --material-tags 悬疑,雨夜 \                      # 可选：素材卡 tags 注入
    --artifacts-dir test-results/ \                 # 测试产出目录（见 §3.4）
    --render \                                      # 可选：真实渲染出片
    --render-limit 3                                # 可选：只渲前 3 镜（快速验证）
```

**参数速查**：

| 参数 | 说明 |
|---|---|
| `--project` | 项目 ID（产物目录名） |
| `--concept` | 创意概念；script 站必填 |
| `--material-tags` | 素材卡 tags（逗号分隔），命中即注入 writer（未命中不影响流程） |
| `--artifacts-dir` | 产物根目录：`test-results/`（测试） / `artifacts/`（正式） |
| `--from` | 断点续跑：`script/art/shoot/prompt/edit/render` |
| `--demo` | 演示模式：内置输出，不调 LLM、无需 key（用于回归） |
| `--qc` | 全链后追加质检（默认检 script 站） |
| `--render` | 真实本地渲染（ComfyUI + LTX 2B）；**不加则只出渲染计划** |
| `--render-limit N` | 只渲前 N 镜（其余 pending），配合 `--render` |

### 3.2 典型场景

| 场景 | 命令 |
|---|---|
| **首次跑通（无 key / 回归）** | `run_pipeline.py --project demo1 --concept x --demo` |
| **测试环境真实跑（¥0）** | `source scripts/scene-env.sh test` + 常规全链（落 `test-results/`） |
| **切换生产环境** | `source scripts/scene-env.sh prod`（剧本走 DeepSeek） |
| **只跑某一段** | `--from shoot`（前置产物已在，自动跳过已完成站） |
| **单站重跑** | `python studios/studio_shoot/run.py --project my-drama --artifacts-dir test-results/` |
| **先验 3 镜再全渲** | `--render --render-limit 3` → 看片满意 → `--from render --render`（全量） |
| **质检** | `--qc`（或 `python studios/studio_qc/run.py --project X --input-stage shoot`） |
| **素材卡预览命中** | `python story-materials/scripts/pick_materials.py --tags 悬疑,雨夜` |

### 3.3 单轮耗时与资源（本地测试档实测）

| 环节 | 实测 |
|---|---|
| 文本五站（script→edit，本地 14b-ctx2k） | 约 5-10 分钟（14 镜项目） |
| 单镜视频渲染（LTX 2B，1024×576，2s） | **约 47 秒**（峰值显存 ~11.3 GB） |
| 全片 14 镜渲染 | **约 11 分钟** |
| 显存硬约束 | **12 GB 卡：渲染必须独占 GPU**（脚本自动卸载 ollama） |

### 3.4 产物目录约定（2026-09-13 定）

| 目录 | 用途 | 入仓 |
|---|---|---|
| `test-results/` | **所有测试产出**（跑测试带 `--artifacts-dir test-results/`） | 仅 README 入仓，产物 gitignore |
| `artifacts/` | **正式产物**（生产运行） | 同左 |
| `plan/` | 设计与方案文档（本地，不入仓） | — |

单个项目目录结构：`<project_id>/manifest.json`（台账+血缘）+ `01_script … 07_qc/`（站产物）

## 4. 当前能力与边界（2026-09-13 快照）

### ✅ 已具备
- **文本七站全链贯通**：concept → 剧本 → 美术 → 分镜 → 提示词 → 剪辑（本地/DeepSeek 双档）
- **分批生成**：长产物按场景分批 + 批内校验 + 逐批重试（根治截断与"静默缺失"）
- **渲染站真实出片**：ComfyUI + LTX-Video 2B 本地渲染，逐镜串行、失败隔离、显存纪律内建
- **两环境切换**：`SCENE_ENV=test|prod`，一键切换
- **血缘 / 断点续跑 / 人工修改保护**
- **测试基线**：pytest 140 例；链路测试台账（`test-results/README.md`）

### ⚠️ 边界与已知限制
| 项 | 现状 |
|---|---|
| **画质** | 本地 LTX 2B = **测试档**（语义偏模糊，成品不合格）→ 成品走 API（roadmap 阶段三） |
| **音频** | 未接入（配乐/配音/音效是成品必需项，roadmap 未定） |
| **QC** | 站已实现（critic 打分 + findings），但**未纳入默认全链**（需显式 `--qc`） |
| **渲染并发** | 串行（显存所限）；无队列/优先级机制 |
| **一致性** | 角色/场景跨镜一致性无专门保障（靠 prompt 描述） |
| **成品档** | minimax API / 云 GPU **未接入**（roadmap 阶段二/三，需预算决策） |

## 6. 运维手册（简要）

**依赖服务**
| 服务 | 端口 | 用途 |
|---|---|---|
| ComfyUI（systemd user） | :8188 | 视频渲染（LTX 2B，模型 symlink 在 `ComfyUI/models/`） |
| ollama | :11434 | 本地 LLM（测试环境） |

**显存纪律（重要）**
- 渲染前**必须**卸载 ollama（脚本已自动处理）——否则 12GB 卡必 OOM
- 渲染期间**禁止**其他 GPU 任务；峰值 ~11.3-11.8 GB
- 模型入位方式：`ln -sf /home/l/opt/models/ltx-video/ltx-video-2b-v0.9.5.safetensors ~/opt/ComfyUI/models/checkpoints/`

**常见故障**
| 症状 | 原因 / 处置 |
|---|---|
| 某站 JSON 解析失败 | 模型输出截断 → 分批已覆盖；若仍发生查 `max_tokens`/ctx |
| 本地模型"空回复" | 批内调用级重试已覆盖；连续失败查 ollama 服务 |
| 渲染 OOM | 先卸 ollama；降分辨率/帧数；或改用 `--render-limit` 分次 |
| `--render` 无产物 | 检查 ComfyUI :8188 与模型 symlink；看 `06_render/render_plan.json` 的 `error` 字段 |
| 站失败后 | `--from <站>` 续跑，已完成产物不会重跑 |

## 7. 已定案的关键决策（勿反复）

1. **剧本后端**：test=本地 ollama / prod=DeepSeek（分环境，不混用）
2. **不做 MiniMax-H3 本地压缩**（33GB 权重，12GB 卡不可用）→ 成品走 API
3. **分批生成**是长产物（分镜/提示词/剪辑）的既定实现（不回落"一次性全量"）
4. **测试产出统一 `test-results/`**；`artifacts/` 只留正式产物
5. **本地视频模型 = 测试档**；成品档走 minimax API / 云 GPU（需预算拍板）
6. **人工修改优先**：`edited_by: human` 产物不被 AI 静默覆盖
