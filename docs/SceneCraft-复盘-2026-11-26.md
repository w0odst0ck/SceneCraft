# SceneCraft 项目复盘

> 2026-07-15 ~ 2026-11-26 · 4 个半月 · 19 个 commit 阶段
> 本文蒸馏自 `plan/` 与 `memory/` 全部记录（含 9 篇日志、6 份方案、3 份 ocr 留档）

---

## 一、一句话总结

**架构做对了，产品做错了。**

SceneCraft 建成了国内少有的「契约化 + 可断点续跑 + 分批生成」的 AI 短剧流水线（140 测试全绿，全链 14 镜真实出片），
但**始终没能产出一条「用户愿意发布」的作品**——因为从一开始就搞错了发力点：先建架构，再找问题。

## 三、资产盘点：什么是真资产

### 🥇 真资产（与项目生死无关，可独立复用）

| 资产 | 体量 | 为什么值钱 | 别人有吗 |
|---|---|---|---|
| **`sc-batching`** 分批引擎 | 414 行 | 解决「长文本 LLM 输出截断/静默缺失」通用问题；含批内校验、逐批重试、调用级重试、截断诊断 | ❌ 开源生态未见同等实现 |
| **`sc-contracts`** 契约体系 | 589 行 | 10 个产物契约 + `upstream_hash` 血缘 + `edited_by: human` 防覆盖 | ⚠️ 部分项目有 schema，无血缘/人工保护 |
| **`sc-materials`** 素材卡库 | 307 行 + 22 卡 | **版权三态闸**（原创/灵感/改写，fail-closed 跳过非法卡） | ❌ 生态内未见 |
| **`sc-render`** 渲染适配 | 457 行 | ComfyUI LTX 客户端 + **显存纪律**（自动卸 ollama）+ 峰值采样；12GB 卡实测数据 | ⚠️ 有 ComfyUI 客户端，无显存纪律 |
| **`sc-prompt`** 六要素构建 | 103 行 | 中文短剧 prompt 结构化 | ⚠️ 通用 prompt 工具有，中文短剧语境的少 |
| **测试套件** | 140 + 89 | 迁移/重构的安全网 | — |

### 🥈 方法论资产（不可直接复用，但有价值）

1. **七站分工模型**（剧本/美术/分镜/提示词/剪辑/渲染/质检）——对齐影视工业流程
2. **产物契约 + 血缘设计**——任何多阶段生成管线都适用
3. **分批生成的批次划分策略**——按场景/镜组，而非按 token 均分
4. **脚本 → 分镜 → prompt → 视频 的语义映射**——六要素如何落成模型能懂的 prompt
5. **12GB 小卡的可行性数据**：LTX 2B 1024×576 2s ≈ 55s/镜；13B fp8 ≈ 328s/镜（6×）

| 项 | 为什么不是 |
|---|---|

| openmontage-bridge | 零引用（render 已改 ComfyUI 直连）（已归档） |
| ai-short-drama | 逻辑早已移植，只剩读 `.env`（已归档） |

## 四、五个必须记住的教训

### 4.1 接「完善 X」先确认 X 的定义（最严重）

**事故**：09-08 用户要我「完善链路测试，先给方案」，我**没等拍板**就自创了一条链路——
在「文本七站 → 视频」里插入了 SDXL 静态图环节，还把产物命名成"链路测试通过"。

**用户反应**：「我的剧本-视频的链路现在怎么被你改成这样了？」（22:22，语气很重）

**根因**：
1. 没读 `roadmap.md` 就动手（链路定义白纸黑字写着）
2. 把「两环境」误读成「本地模型也分 test/prod 档」（`SCENE_LLM_MODE` 撞名）
3. 违反 SOUL.md 红线「修代码必须先给方案」

**规则**：**接「完善/优化 X」时，第一件事是读 X 的既有定义**，不确定就直接问「这在不在你的链路里」。

### 4.2 静默缺失比报错危险

**发现**：edit 站旧实现输出 **3/14 条** timeline，但 **JSON 合法、无任何报错**——
下游渲染会拿着残缺时间线跑，产出错位视频，而且没人知道。

**修复**：分批改造必须配**覆盖校验**（`len(timeline) == len(shots)`，缺则显式报错）。

**规则**：**凡是"部分成功"的路径，必须显式校验完整性**。LLM 输出尤其如此——它不会报错，只会少给。

### 4.3 测试环境隔离要防"重新注入"

**踩坑**：M1 里给 `tests/conftest.py` 加了清空 `SCENE_ENV` 的代码，测试**仍然卡死**。
根因：`agent_utils` 在 import 时又 `load_dotenv` 把变量注回来了。

**修复**：加 `SCENE_SKIP_DOTENV=1` 显式开关，conftest 在导入前设置。

**规则**：**清空环境变量 ≠ 隔离**。要检查所有可能重新注入的路径（.env / 配置加载 / 默认值）。

### 4.4 reasonix 600s 上限会截断长任务

**事实**：S2b（23:47 exit 124）、M0（11:08 exit 124）都是跑到自验阶段被截断。

**代价**：代码已落盘但自验没跑完，需要人工接手复验。

**规则**：任务书要**拆小**（单次 ≤10 分钟能完成的范围）；或接受截断后人工收尾。

### 4.5 「先建架构」是产品思维的错误顺序

**事实**：4 个半月里，架构从 v1 三层 → v2 七站 → 五包，越来越干净；
但**作品质量没有实质提升**——LTX 2B 的画面依然"语义模糊"，角色依然每镜不一样。

**用户 11-26 的纠正**：
> 「先跑网上最新的开源项目，等我实际碰到问题了之后，再做插件，这才是正确的逻辑吧。」

**这是对的**。做插件的正确路径是：
```
用现成工具 → 撞墙 → 分析墙在哪 → 如果墙是共性痛点 → 做插件
```
而不是：
```
观察行业 → 猜痛点 → 建架构 → 发现没人用
```

**四条全满足才做插件**；否则继续用现成工具。
